🍎 Start chromeTerminal when macOS starts

After you sign in, a user LaunchAgent starts the keeper, and the keeper keeps http://127.0.0.1:3847 up. This is your login session — not a root daemon — so the PTY can use your zsh, nvm node, and ~/projects.

What gets installed

Piece Where
LaunchAgent label com.rifaterdemsahin.chrometerminal
Plist ~/Library/LaunchAgents/com.rifaterdemsahin.chrometerminal.plist
Command /bin/zsh -lc 'cd …/chromeTerminal && exec node scripts/keep-alive.js'
Port 127.0.0.1:3847
Stdout ~/Library/Logs/chromeTerminal.out.log
Stderr ~/Library/Logs/chromeTerminal.err.log

RunAtLoad starts it at login. KeepAlive means launchd restarts the keeper if that process exits. The keeper then restarts server.js if the process crashes or /health fails.

Install

cd ~/projects/chromeTerminal
npm install
npm run macos-install

That writes the plist, bootouts any old copy, then launchctl bootstrap gui/$(id -u). You do not need to reboot; the agent starts immediately and will also start the next time you log in.

Check that it is running

curl -s http://127.0.0.1:3847/health
launchctl print gui/$(id -u)/com.rifaterdemsahin.chrometerminal | head
tail -f ~/Library/Logs/chromeTerminal.out.log

Health should look like {"ok":true,"port":3847,…}. Open Chrome at http://127.0.0.1:3847.

Uninstall

npm run macos-uninstall

Stops the agent and deletes the plist. Port 3847 will go down unless you run npm start yourself.

Login vs boot

This is not a LaunchDaemon at boot (before anyone logs in). A daemon would run as root and could not safely attach to your interactive shell. “When the Mac starts” here means: when you log in.

Do not run two keepers

If the LaunchAgent is loaded, you usually should not also run npm start in a terminal. Two keepers will fight over port 3847 (the extra one will crash and back off). Use the agent for everyday use; npm run macos-uninstall first if you want a manual npm start or npm run dev.
